# Forms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Rage, Bladesong, Innate Sorcery, Dragon Wings and Holy Nimbus be started and ended over the API, with their modifiers counting in the sheet's numbers while active.

**Architecture:** Features declare a `form`; any modifier can name a form with `form`. A new `resolveForms` step in `Compute`, run before `activeMods`, strips the form gate from modifiers of active forms and folds it into `Condition` for inactive ones, so the rest of the pipeline is unchanged. Per-activation picks are `form_choices`, which reuse `Choice`/`Option`. `ApplyForm` spends a use through the existing `ResourceUsed` bookkeeping.

**Tech Stack:** Go (package `character`, repo root), JSON content packs under `content/`, `go test`.

**Spec:** `docs/superpowers/specs/2026-11-11-forms-design.md`

## Global Constraints

- Everything is API-driven; no Discord changes.
- Off-state condition text is exactly `while <Name> is active`, joined to any existing condition with `, ` (e.g. `while Rage is active, against spells cast by fiends or undead`).
- Form ids: `rage`, `bladesong`, `innate_sorcery`, `dragon_wings`, `holy_nimbus`.
- New requires values: `strength_attack`, `only_caster:<class id>`.
- New warning codes: `form_unavailable`, `form_pick_missing`, `form_pick_invalid`, `form_unknown`.
- API errors: 400 `bad_request` for bad input, 409 `no_uses` when no use is left.
- Long rest clears `active_forms`; short rest does not. Ending refunds nothing.
- Warnings stay permissive (stale stored state never fails Compute); only the start action rejects.

## Review Focus

1. A character who lost the form's feature (respec, removed subclass) but still has it in `active_forms`: the sheet warns `form_unavailable`, numbers ignore it, and `end` still removes it (Task 4 test `TestApplyFormEndRemovesUnavailable`).
2. Rage off: the Strength-attack damage tiers carry a weapon requirement, so they live in `calc.weaponMods`. They must still show in `Sheet.Notes`, not vanish (Task 5 test asserts a `damage.all` note with condition `while Rage is active`).
3. Rage's resource comes from its tier, not the feature; the form's resource id must come from `resOf` after tiers are applied (Task 2 `TestFormsResourceFromTier`).
4. Starting a form when `ResourceUsed` was `set` above the max (or exactly at it) must 409, not go further over (Task 4 `TestApplyFormNoUses`).
5. A stored pick for a choice whose declaring feature the character no longer has (left Wild Heart) is ignored with `form_pick_invalid`, never applied (Task 2 `TestFormsStalePicks`).

- Produces:
  - `gathered.forms []formEntry` where `type formEntry struct { def FormDef; featureID string; resourceID string }` and `gathered.formChoices []formChoiceEntry` (`featureID string; fc FormChoice`)

  - `Compute` pipeline becomes `dedupe(resolveAbilityValues(c, activeMods(g, resolveForms(c, g, g.mods))))`. Change `activeMods` to take the mods slice: `func activeMods(g *gathered, mods []Modifier) []Modifier`.
