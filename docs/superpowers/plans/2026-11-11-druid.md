# Druid and Circle of the Moon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Druid class with Circle of the Moon, where Wild Shape is a form that substitutes a Beast's stat block into the computed sheet.

**Architecture:** Wild Shape is a `FormDef` with a `shape` block. Known Forms are a choice the shape synthesises on its feature. While a shape form is active, `Compute` substitutes the beast's numbers at each point it computes them (abilities, saves, skills, AC, initiative, speeds, senses, attacks), so everything downstream reads the shaped values; `Sheet.Shape` describes the beast. Moon's riders are ordinary content: `value_formula` modifiers on new `shape.*` targets and an AC formula tied to the form.

**Tech Stack:** Go (package `character` at the repo root), JSON content packs under `content/`.

**Spec:** `docs/superpowers/specs/2026-11-11-druid-design.md`

## Global Constraints

- Branch `druid`, which is based on `temp-forms`. Run `go test ./...` before every commit; it must pass.
- `content/` is gitignored on purpose (commit fce590a). Content edits stay in the working tree, uncommitted; commit only Go files, tests, docs and `openapi.json`.
- Validation is permissive: rules problems in stored state are `Warning`s, never compute errors. Bad content is a loader error.
- CR strings: `"0"`, `"1/8"`, `"1/4"`, `"1/2"`, or an integer `"1"`..`"30"`.
- New modifier targets: `shape.max_cr` (kind `min`), `shape.temp_hp` (kind `set`), `shape.cast_spells` (kind `set`, value 1).
- New warning codes: `shape_unknown_creature`, `shape_not_known`, `shape_ineligible`.
- Known Forms choice id: `known_forms`. Form id `wild_shape`, name `Wild Shape`. Creature tag `wild_shape`.
- Ineligible reasons, exactly: `CR <cr> is above your max of <max>` and `has a fly speed, which <Form Name> allows from level <n>`.
- API errors: 400 `bad_request`, 409 `no_uses`, through the existing `badReq` / `noUses` helpers.
- Match surrounding code: comment density, naming, table-driven tests where neighbours use them.

## Rulings made while planning (spec deviations, recorded for review)

1. **Substitution happens in place, not as a post-pass.** The spec names an `applyShape` step that "rewrites the sheet". Rewriting afterwards would leave AC, initiative, skills and attacks computed from the Druid's Dex, so the beast's values are substituted where each is computed. The behaviour table in the spec is unchanged.
2. **Speeds and physical scores are the beast's, without the character's modifiers.** A species' base walk speed and its ability bonuses are themselves modifiers (`speed.walk add 30`, `ability.str add 1`), so "beast speed + speed modifiers" would give a wolf 70 ft. While shaped, `Speeds` are exactly the beast's and Str/Dex/Con are exactly the beast's scores. Every other modifier (saves, skills, AC, attacks, damage, initiative, resistances, senses) still applies. Cost if wrong: a Barbarian/Druid loses Fast Movement while shaped.
3. **Max HP and resource maximums use the character's own Con and modifiers**, not the beast's ("you retain your Hit Points").
4. **FormView also carries `fly_allowed` and `temp_hp`** (the temp HP starting the form would grant), so `ApplyForm` and clients don't recompute them.
5. **Cure Wounds already exists as `cure_wounds_2024`** in the classes pack; the Druid list and Moon spells use that id. Only 15 Druid spells are missing (Task 7).
6. **Potent Spellcasting uses the existing `damage.cantrip.druid` target** and Magician's extra cantrip uses `spell.cantrips.druid`, as the Cleric's Thaumaturge and Potent Spellcasting do.
7. **Feature-granted attack actions stay while shaped**; weapon attacks and Unarmed Strike are replaced by the beast's attacks.

## Review Focus

1. A Barbarian/Druid raging while shaped: Rage's `strength_attack` damage applies to a beast attack whose to-hit uses Str. (Task 4 test.)
2. Ending Wild Shape restores the Druid's own numbers and the Unarmed Strike. (Task 4 test.)
3. `active_forms` written through PUT with a shape form but no `creature_id`: warns `shape_unknown_creature`, no overlay, no crash. (Task 4 test.)
4. Armour worn while shaped doesn't count toward AC. (Task 4 test.)
5. Starting Wild Shape with no Known Forms picked: 400 naming the problem, nothing spent. (Task 5 test.)
