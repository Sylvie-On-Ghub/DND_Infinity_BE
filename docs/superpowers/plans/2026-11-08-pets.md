# Pets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Characters own pets (Find Familiar, Pact of the Chain, later Primal Companion) whose stat blocks
come from library content, scale with the owner, and carry play state.

**Architecture:** A new `Creature` content kind loaded from `creatures/`. `Character.Pets` stores owned
pets. `Compute` sets owner modifiers aimed at pets (`pet.<tag>.*`) aside, finishes the owner's sheet as
today, then builds a `PetView` per pet in a new `pets.go`, evaluating creature formulas with an owner
context. Play-state actions live in `petactions.go` and are routed under
`/api/characters/{id}/pets` like inventory.

**Tech Stack:** Go standard library only; SQLite store unchanged (pets ride in the character JSON).

**Spec:** `docs/superpowers/specs/2026-11-08-pets-design.md`

## Global Constraints

- Rules problems are warnings on the sheet, never rejections (spec: "Permissive").
- Request bodies are strict: unknown fields are a 400 (existing `readJSON`).
- Content loading is strict: unknown JSON fields are errors.
- Pet statuses are exactly `active`, `dismissed`, `dead`.
- `PB` nil on a creature means 2.
- Owner terms: `owner.mod.<ability>`, `owner.pb`, `owner.level`, `owner.class_level.<id>`, `owner.spell_attack`, `owner.spell_save_dc`.
- Pet target form: `pet.<tag>.<inner target>`, built with `PetTarget(tag, target)`.
- Note placeholders: `{owner.spell_save_dc}` and `{owner.spell_attack}`.
- Match surrounding style: doc comments on types, short inline comments, `mkWarning`, `badReq`.
- Run the whole suite with `go test ./...` before each commit; content-backed tests skip without `content/`.

## Review Focus

1. **A stored pet whose creature disappears from content** (pack edited or reloaded): the sheet must still list it with its play state and a warning, never drop it or 500. Test in Task 4.
2. **Recasting into an unknown form** (`PATCH creature_id` to a missing id): 400, and the pet is unchanged. Test in Task 6.
3. **Damage on a pet with temp HP, healing a dead pet, healing past max**: temp absorbs first, a dead pet stays at 0 and `dead`, heals cap at max. Test in Task 6.
4. **Owner loses the source** (respec drops Pact of the Chain, or levels down): the pet gets a `pet_source_missing` warning and `owner.spell_*` terms resolve to 0 with a warning, without crashing. Test in Task 5.
5. **One familiar at a time with a dismissed one**: two `active` pets from one source warn, but an `active` plus a `dismissed` do not. Test in Task 5.

### Task 4: Compute pet views

**Files:**
- Create: `pets.go`
- Modify: `character.go` (`Sheet.Pets`, `PetView`, `PetAttackView` exactly as spec Section 2), `compute.go` (call at the end of `Compute`)
- Test: `pets_test.go`

**Interfaces:**
- Consumes: `formulaCtx`/`ownerCtx`/`evalFormula` (Task 2), `Sheet.petMods`, `splitPetTarget` (Task 3), `Library.Creature` (Task 1).
- Produces: `func petView(p Pet, c Character, sh Sheet, lib Library, skillDefs []SkillDef) PetView` — pure; used by `Compute` and by Task 6 for max HP.
- Produces: `func ownerSpellSource(sh Sheet, lib Library, sourceID string) (SpellSourceView, bool)`:
  1. a feature in `sh.Features` with `FeatureID == sourceID`: if `lib.Feature(sourceID)` has `Spells`, the source with ID `"feature:"+sourceID`; else if its `Source == OriginClass`, `"class:"+SourceID`;
  2. otherwise the first `sh.Spellcasting` source whose `Spells` or `Cantrips` contain a spell with `ID == sourceID`;
  3. otherwise not found.
- `Compute` sets `sh.Pets = []PetView{}` (never null) and appends `petView` for each `c.Pets` in order.

Rules `petView` follows (each pinned by a test below):
- Pet ability mod = `(score-10)/2` floored; save bonus = mod + PB if in `Saves`, plus `save.<ab>`/`save.all` mods.
- PB = `evalFormula(*PB)` or 2. AC, MaxHP from formulas, then `calc.apply(TargetAC|TargetMaxHP, v)`.
- Skills: only those in `creature.Skills`, bonus = ability mod + PB×(1 trained, 2 expert) + `skill.<id>` mods; ability from `skillDefs`.
- Speeds: creature speeds then `calc.apply(SpeedTarget(s), v)` for every speed type (so a `ModMin 40 fly` creates a fly speed).
- Attack to-hit = `ToHit` + `attack.all` sum; damage string = dice + signed flat (`Damage` + `damage.all`), e.g. `"1d8+5 piercing"`, `"1 slashing"` when no dice, `"1d4-1 piercing"`. Range `"reach 5 ft."` or `"80/320 ft."`.
- Modifier order: creature `Modifiers`, then owner `petMods` whose tag is in creature `Tags` (prefix stripped), then `p.Modifiers`; `dedupe` then `newCalc`.
- Notes: every `ModNote` and situational modifier, with `{owner.spell_save_dc}`/`{owner.spell_attack}` replaced by the resolved number in `Note`.
- Resistances/immunities: creature lists plus `calc.damageList("resist."/"immune.")`, deduped.
- Unknown creature: PetView with ID, Name, CreatureID, SourceID, Status, HP fields, Conditions, empty slices, and an `unknown_id` warning (`WarnUnknownID`, value = creature id).
